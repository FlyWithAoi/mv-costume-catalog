# 衣装グループ分類ルール

`costumes.json` の各衣装が持つ `costume_group` と `tags` の運用ルールをまとめたメモです。大量登録の前に分類方針を軽く固定し、後から見返せるようにするのが目的です。

対象コミット基準: `e528f06 chore: ignore claude workspace files`

> このドキュメントは分類の**運用ルール**です。今回の追記時点で `costumes.json` の分類は修正していません（既存データの見直しは、大量登録後のレビューでまとめて行う想定。6章参照）。

---

## 1. 基本方針

- `costume_group` は、衣装の**主な入手元・実装カテゴリ**を表す。
- 分類が曖昧なときは、無理に推測せず `other` にして、後から見直す。
- `costume_group` や `tags` は、**画像や衣装データを追加した後でも修正できる**。
  - 分類の修正だけなら、画像の作り直しは不要（`costumes.json` を書き換えるだけ）。
- 1レコード＝「アイドル1人の衣装1着」なので、`costume_group` も衣装1着に対して1つだけ付ける。

---

## 2. SCR（シークレットカラー）の扱い

SCR は `costume_group` ではなく、**補助属性**として扱う。

理由:

- SCR は星5カード衣装などに付く「差分」であり、他の衣装カテゴリと**同時に成立する**。
- 例: クロススカウト衣装の SCR、フィーチャースカウト衣装の SCR、共通衣装の SCR。

つまり「SCR かどうか」と「どのカテゴリの衣装か」は別の軸なので、`costume_group` を SCR で埋めてしまうと本来のカテゴリが表現できなくなる。

現時点の運用: SCR は `tags` に `"SCR"` を入れる。

例（クロススカウト衣装の SCR）:

```json
{
  "costume_group": "cross",
  "tags": ["SCR"]
}
```

例（共通衣装の SCR）:

```json
{
  "costume_group": "common",
  "tags": ["SCR"]
}
```

将来、SCR だけで絞り込みたくなった場合は、`is_scr: true` のような専用フィールドの追加を検討する（今回は追加しない。9章の将来メモ扱い）。

---

## 3. 現時点の costume_group 候補

| 値 | 意味 |
|---|---|
| `common` | 共通アイドル衣装など、全員または多くのアイドルが持つ基本衣装 |
| `unit` | ユニット衣装 |
| `feature` | フィーチャースカウト衣装 |
| `scout` | 通常スカウト衣装 |
| `cross` | クロススカウト衣装 |
| `shuffle` | シャッフル衣装 |
| `event` | イベント衣装 |
| `exchange` | 交換所・ショップ・全アイドル分が用意される交換系衣装 |
| `campaign` | 記念配布・キャンペーン系衣装 |
| `other` | その他・未分類・判断保留 |

補足:

- Caelum のような**全アイドル分がある交換衣装**は、`cross` ではなく `exchange` 寄りとして扱う。
- フィーチャースカウト衣装は、ユーザー間で「フィーチャー1」「フィーチャー2」などと呼ばれることがあるため、必要に応じて `tags` に `"フィーチャー1"` / `"フィーチャー2"` を入れる。
- **通常スカウト（`scout`）とクロススカウト（`cross`）は別カテゴリ**として扱う。
- 迷う場合は `other` にして、後から確認する。

---

## 4. tags の使い方

`tags` は、主分類（`costume_group`）とは別の**補助情報**に使う。

例:

- `"SCR"`
- `"フィーチャー1"`
- `"フィーチャー2"`
- `"全アイドル"`
- `"交換衣装"`
- `"暫定分類"`（分類に自信がなく、後で見直したい印）

ただし、タグを増やしすぎると管理が大変になるため、**最初は必要最小限**にする。「後で自分が絞り込みたい／レビューしたい軸」だけをタグにするのが目安。

---

## 5. 複数ユニット所属の扱い

三毛縞 斑や桜河 こはくのように、複数ユニットに所属させたいアイドルがいる。

例:

- 三毛縞 斑: MaM / Double Face
- 桜河 こはく: Crazy:B / Double Face

現在の設計では、`units.json` の各ユニットの `member_slugs` に**同じ `idol_slug` を入れる**ことで複数ユニット所属を表現する。アイドル側に「所属ユニット一覧」を持たせるのではなく、ユニット側のメンバー表を正とする（`docs/project-notes.md` 5章参照）。

例:

```json
{
  "slug": "mam",
  "name": "MaM",
  "member_slugs": ["mikejima-madara"]
}
```

```json
{
  "slug": "double-face",
  "name": "Double Face",
  "member_slugs": ["mikejima-madara", "oukawa-kohaku"]
}
```

この場合、三毛縞 斑の衣装は **MaM 検索でも Double Face 検索でもヒットする**想定（ユニット名検索は所属アイドル経由で判定するため）。

注意: `member_slugs` に入れる `idol_slug` は、必ず `idols.json` に存在するものにする（存在しないと表示が「不明なアイドル」にフォールバックする）。

## 6. 今後の見直し方針

衣装を大量登録したあとに、分類レビューをまとめて行う。

レビュー時に重点的に見るもの:

- `costume_group: "other"` の衣装
- `tags` に `"暫定分類"` が付いている衣装
- Caelum など交換系・全アイドル系衣装（`exchange` 寄りに寄せられているか）
- SCR 衣装（`tags: ["SCR"]` になっているか）
- フィーチャースカウト 1 / 2 の区別
- 通常スカウト（`scout`）とクロススカウト（`cross`）の判定

分類の修正は `costumes.json` の変更だけで済むため、**画像生成をやり直す必要はない**。
